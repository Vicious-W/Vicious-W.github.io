## Owner objective

下一阶段重建第一屏的第一层玻璃和第三层反应堆：

1. 继续优化玻璃立方体，使物理手感更有重量、更稳定，玻璃质感更真实，并让实际物理运动产生对应声音。
2. 推翻目前像贴图的反应堆主体。根据真实核反应堆的公开结构资料，将主要部分分别建模，使各部分拥有独立状态和可信运行关系，最终形成真正的三维、物理化反应堆场景。

## Workstream A: glass physics, material, and sound

### Required implementation

- 审计并重新调节 cannon-es 的质量、惯性、重心、重力、线性/角阻尼、静摩擦/动摩擦、恢复系数、休眠阈值、solver 和接触参数。
- 拖拽仍使用物理约束，但手的运动、抓取点、最大作用力和释放速度必须让方块有重量，避免像被无质量指针吊着漂移。
- 保持稳定堆叠和方块间碰撞，消除明显悬空、持续微抖、过度弹跳、穿透和爆炸式速度。
- 重做玻璃厚度、折射率、透射、体吸收、粗糙度、边缘/倒角高光、接触阴影和与水下蓝光的关系。透明不等于无形，也不能读成蓝色塑料。
- 使用 Web Audio API 建立程序化或采样式玻璃声音层。撞击声音由接触冲量和相对速度触发；滑动/滚动声音由持续接触状态驱动；位置映射到立体声/空间声场。
- 音频只在用户首次手势后解锁；具有节流、voice 上限、增益压缩/限幅和极小碰撞过滤，避免物理引擎在静止接触时制造噪声风暴。

### Acceptance evidence

- Playwright MCP 实际拖拽、释放、碰撞和堆叠；视频帧/截图能显示释放后的稳定接触和真实材质。
- 浏览器检查确认 AudioContext 在用户手势前不违规启动、手势后可运行；碰撞事件与声音触发之间有可审查的物理数据映射。
- 桌面、平板、移动视口均不因音频或物理更新出现 console error、明显掉帧或页面不可操作。

## Workstream B: physical 3D reactor reconstruction

### Research before modeling

- 从官方机构、研究设施、大学或其他可靠公开来源选择一种与现有“从水池上方俯视堆芯”构图相符、资料足够的研究堆原型或严格定义的组合参考。
- 在 `PROJECT.md` 和实现报告中记录选择、公开来源、哪些结构来自资料、哪些视觉细节是为网页表达做的合理抽象。
- 不把商业压水堆压力容器内部结构与开放式研究堆水池随意混合，也不继续沿用明显不符合所选原型的旧图案。

### Required independent systems

依据最终原型，至少分别建立并组织：

- 水池/容器、内衬、井壁和顶部结构；
- 堆芯支撑结构、栅格或反射体；
- 多个可辨认的燃料组件，不是一整张发光棋盘；
- 控制棒或等价控制机构及其驱动/导向结构；
- 原型中可从当前视角表达的冷却、循环、管路或仪器结构；
- 水体、切伦科夫辉光和必要的照明/阴影关系。

每个主要系统需要独立的场景对象、材质和状态。至少实现一条可解释的运行链：控制机构状态变化 → 堆芯功率代理变化 → 水体/切伦科夫辉光/相关仪器的可见响应。运动速度和幅度应克制、机械可信。

### Architecture and fallback

- 正式主体使用 Three.js 真三维几何；允许通过 InstancedMesh、程序化几何和 LOD 控制成本，但不能把主体重新烘成一张平面图。
- 现有 `reactorShader.js`/原生 WebGL 池面保留为首屏瞬开和加载失败降级，不再冒充最终反应堆结构。
- 继续限制 DPR、延迟加载重型模块、离屏暂停、处理 WebGL context lost，并保持 GitHub Pages 静态部署。

### Acceptance evidence

- 从视差、遮挡、光照、边缘和各部件独立运动可以确认主体是三维模型，而非 shader 贴图。
- 代码场景图中能定位主要系统的独立对象、状态和更新逻辑。
- 控制机构运行链可实际触发并被 Playwright MCP 观察；不是几组互不相关的循环动画。
- `390 × 844`、`768 × 1024`、`1440 × 900` 均有成立的构图和可用交互；console 无影响页面的错误。

## Scope boundaries

- 本任务只重建第一屏背景与交互，不决定第一屏文字如何回归，也不重做第二、三、四屏。
- “真实运行”是网页范围内结构、机械、材料、光学和状态耦合可信，不是工程级核物理、热工水力或安全分析软件。
- 不引入后端、在线服务、运行时密钥、自动部署或不受控网络依赖。
