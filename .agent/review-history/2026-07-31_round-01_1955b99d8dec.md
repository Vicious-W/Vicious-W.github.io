## Major

### R-001: 自动回收候选点未实际约束轨迹或触发失配重规划

- Severity: Major
- Requirement: `PROJECT_SPEC.md` §6.5、§10.4；`docs/engineering/FLY_PHYSICS.md` §11。自动系统应根据风层和候选点控制高度，候选点不可达时重新选择，并真实接近所选安全区域。
- Evidence: `src/scenes/fly/recovery/recoveryPlanner.js:54-75` 的 `recoveryControls()` 除了判断 `plan.selected` 是否存在外，不读取候选点坐标、`eta`、`alongDistance`、预测航迹或风层；它仅按当前 AGL、垂直速度和正下方地表执行通用下降。1440×900 浏览器流程中，请求位置约为 `(132.99, 98.15, 33.25)`，候选点为 `(549.24, 198.45)`；整个回收仅记录一个计划，最终接地点为 `(755.39, 244.97)`，距候选点约 `211.3 m`，且已经进入另一个 160 m 地表单元，但未重规划。
- Location: `src/scenes/fly/recovery/recoveryPlanner.js:54-75`；`src/scenes/fly/flySession.js:61-75`
- Impact: 候选评估目前主要是调试记录。自动系统会立即执行通用下降，再依赖正下方地表恰好安全；在水面、树林或道路连续区域中无法证明它会利用风层接近所选区域，核心“自动安全降落”因果链未成立。
- Reproduction:
  1. 在 1440×900 进入 FLY，燃烧至自由飞行并漂移到约 90 m AGL。
  2. 请求自动回收，记录 `window.__FLY__.session.recovery.selected`。
  3. 用同一固定步推进至 `RECOVERED`，比较接地点与候选点，并检查 `window.__FLY__.evidence().recoveryPlans`。
- Expected: 自动控制根据候选点的预计到达时间、风层和预测偏差安排高度；当预测越过候选区或偏差超出安全余量时产生新计划。
- Actual: 控制律不使用候选位置；本次轨迹越过候选点约 211.3 m，仍只保留最初一份计划。
- Acceptance criteria: 在包含连续 WATER、FOREST、ROAD 和 FIELD 单元的多种固定种子测试中，记录每次候选、预计轨迹和实际接地点；接地点必须位于当前计划规定的安全区域及声明容差内，或在预测失配前产生新计划；全程不得接触不安全地表，规划器仍不得写入位姿。
- Suggested direction: 将沿风进度、候选 ETA、预计落点偏差和不同高度风样本接入 `recoveryControls()` 与重规划条件。

### R-002: 多指输入会在取消后遗留燃烧器持续开启

- Severity: Major
- Requirement: `PROJECT_SPEC.md` §6.4、§10.5；`docs/engineering/FLY_SCENE_ARCHITECTURE.md` §9。触控必须处理多指取消，`pointercancel` 或 pointer capture 丢失后持续输入立即归零。
- Evidence: `src/scenes/fly/flyScene.js:87-88` 仅保存一个全局 `activeControlPointer` 和 `activeControlAction`；第二根手指会覆盖第一根手指的所有权，`release()` 又按当前 action/pointer 过滤。390×844 的干净新会话实测状态为：`0/0 → pointerdown(burner)=1/0 → pointerdown(vent)=1/1 → pointercancel(burner)=1/1 → pointerup(vent)=1/0`；燃烧器按钮仍有 `is-active`，直到额外触发 `window.blur` 才归零。
- Location: `src/scenes/fly/flyScene.js:87-88`、`src/scenes/fly/flyScene.js:260-276`
- Impact: 移动端用户同时触碰燃烧器与 vent 后，取消先前触点可能让燃烧器继续消耗燃料和加热，形成直接影响飞行安全的卡键状态。
- Reproduction:
  1. 在 390×844 出发，确认 `manualControls` 为 `{burner:0, vent:0}`。
  2. 以 pointer 61 按住 burner，再以 pointer 62 按住 vent。
  3. 对 burner 发送 `pointercancel`，随后释放 vent。
  4. 检查 `window.__FLY__.session.manualControls` 和按钮 class。
- Expected: 每个持续控件独立跟踪 pointer；任意 pointer 的取消只释放其拥有的动作，所有触点结束后两项输入均为零。
- Actual: 第二根手指覆盖第一根手指的记录，第一根手指取消被忽略，burner 保持为 1。
- Acceptance criteria: 自动化覆盖 burner→vent、vent→burner、不同释放顺序、任一触点 `pointercancel`/`lostpointercapture` 以及全局 blur/hidden；每个动作在其所属触点结束后立即归零，不得遗留 active class 或燃料消耗。
- Suggested direction: 按 `pointerId` 保存动作所有权，或分别为 burner/vent 保存活动 pointer 集合。

### R-003: 浮动原点迁移没有同步平移相机

- Severity: Major
- Requirement: `PROJECT_SPEC.md` §5.1、§10.4 及 `.agent/next-task.md` 的定量验收。原点迁移前后相机相对关系连续，画面位移误差不超过 1 CSS 像素。
- Evidence: `world.maybeShiftOrigin()` 在固定步中立即切换 128 m 对齐的原点；随后 `balloonModel.update()` 和 `worldView.sync()` 立即减去新原点。`src/scenes/fly/flyScene.js:348-371` 只重新计算相机目标并从旧局部坐标执行 `camera.position.lerp()`，没有先对相机应用同一 `shift.delta`。以 60 Hz PILOT 阻尼系数约 `0.2` 计算，128 m 迁移后的首帧仍留下约 `102 m` 的相对误差。浏览器完整旅程记录到 7 次迁移，但现有测试只验证逻辑坐标、区块数和迁移次数，没有检查投影连续性。
- Location: `src/scenes/fly/world/proceduralWorld.js:66-78`；`src/scenes/fly/flyScene.js:348-371`；`src/scenes/fly/flyScene.js:389-392`
- Impact: 迁移时地形、热气球和云立即换到新局部坐标，而相机缓慢追赶，可能产生明显整世界跳动，破坏“无限航行”核心体验。
- Reproduction:
  1. 在 PILOT、CHASE 或 ORBIT 飞行至水平局部距离超过 96 m。
  2. 在 `originShiftCount` 增加的前后帧记录相机与同一世界锚点的屏幕投影。
  3. 比较首帧投影差和相机追赶过程。
- Expected: 原点迁移步内，相机先应用与全部局部对象相同的 `-shift.delta`，再继续正常舒适阻尼；屏幕投影变化不超过 1 CSS 像素。
- Actual: 对象立即迁移，相机只通过后续 lerp 追向新位置。
- Acceptance criteria: 为 PILOT、CHASE、ORBIT 在 30/60/120 Hz 下记录迁移前后固定世界锚点与飞行器的屏幕投影；每次迁移误差不超过 1 CSS 像素，速度、风样本和音频参数连续。
- Suggested direction: 在消费原点事件时先平移相机和其他局部观察状态，再计算该帧目标。

### R-004: 篮筐着陆与近场障碍物没有规格要求的物理载荷路径

- Severity: Major
- Requirement: `PROJECT_SPEC.md` §5.1、§6.3、§6.5、§10.4。篮筐着陆应包含碰撞、阻尼、倾倒/拖曳可能性；近场树木、建筑等障碍应参与碰撞，安全查询与实际碰撞使用同一数据。
- Evidence: `src/scenes/fly/vehicles/hotAirBalloon.js:62-67` 的 basket 没有姿态、角速度、惯性或碰撞形状；`src/scenes/fly/vehicles/hotAirBalloon.js:133-149` 仅把中心高度夹到地面，反转少量竖直速度并缩放水平速度。`basket.tilt` 在 `:158-163` 只平滑跟随悬挂摆角，不由接触力矩产生。`src/scenes/fly/worldView.js:105-131` 的树木只是 `InstancedMesh`，没有碰撞代理；`terrainAt()` 仅返回 `obstacleDensity`/`safe` 元数据。实现报告的 `FLY-GAP-003` 也明确承认没有单树/建筑/线路碰撞及完整篮筐边缘/倾倒接触。
- Location: `src/scenes/fly/vehicles/hotAirBalloon.js:62-67`、`src/scenes/fly/vehicles/hotAirBalloon.js:133-163`；`src/scenes/fly/worldView.js:105-131`
- Impact: 高水平速度或偏心接地不能产生真实倾倒、拖曳或边缘碰撞；热气球可穿过可见树木。安全规划读取的障碍元数据与实际物理接触不是同一系统，因此无法证明自动回收不会穿越已标记障碍。
- Reproduction:
  1. 让篮筐以水平速度接近 FOREST 区的可见树木或以偏心姿态接地。
  2. 检查 basket 快照及接触状态。
  3. 观察只有地形高度夹紧和速度缩放，没有树木接触、角动量、倾倒或拖曳状态。
- Expected: 近场障碍拥有与安全查询一致的碰撞代理；篮筐碰撞形状和角动力学能够产生接触力矩、倾倒、弹跳及拖曳。
- Actual: 当前只有解析地形的单点竖直接触和可视化摆角。
- Acceptance criteria: 增加可验证的篮筐碰撞形状、姿态/角速度/惯性和多点接触；固定测试覆盖安全低速着陆、高速拖曳、边缘倾倒及树木/建筑/线路碰撞；自动规划使用同一障碍身份和几何，轨迹不得穿透。
- Suggested direction: 可采用有界多点接触和近场代理，不要求完整柔体或逐树全世界刚体。

### R-005: FLY_CONFIG 绕过了气象和飞行器选择流程

- Severity: Major
- Requirement: `PROJECT_SPEC.md` §3.1；`docs/engineering/FLY_SCENE_ARCHITECTURE.md` §6。即使第一阶段只有一项，也必须经过注册表驱动的选中状态和确认事件，并由气象状态提供出发空间反馈。
- Evidence: 浏览器进入 FLY 后显示 `FLY_CONFIG / NONE`，但点击画布任意位置便直接打开指南。`src/scenes/fly/flyScene.js:140-155` 只建立热气球和静态圆形地面；没有 weather preview 或选项控件。`src/scenes/fly/flyScene.js:292-294` 在没有 session 时无条件调用 `openGuide()`，不执行命中选择。`startFlight()` 在 `:183-187` 直接使用 `DEFAULT_FLY_SELECTION`。调试接口的 `registries.selected` 也是固定常量，而非用户确认的会话选择。
- Location: `src/scenes/fly/flyScene.js:140-155`、`src/scenes/fly/flyScene.js:183-205`、`src/scenes/fly/flyScene.js:292-294`
- Impact: 当前配置空间只是通往指南的全画布按钮，注册表没有真正控制体验状态。以后加入第二种气象或飞行器时，仍需重写主流程，未达到本轮要求的可复用选择基础。
- Reproduction:
  1. 从 SITE_SELECT 进入 FLY。
  2. 不选择任何模型或气象，在空白天空位置点击画布。
  3. 观察指南直接出现，随后出发固定创建 `clear + hotAirBalloonC100`。
- Expected: 用户通过无文字三维对象确认当前气象和飞行器；选中状态来自注册表，出发空间读取气象预览，确认后将所选 ID 锁入 session。
- Actual: 任意画布点击都确认固定默认值，未存在独立选择状态或气象预览。
- Acceptance criteria: 配置状态分别记录 `weatherId`、`vehicleId` 和确认状态；只能通过对应无文字三维对象完成选择/确认；session 使用已确认 ID；测试验证兼容性、空白点击不确认及注册项增加后无需修改飞行主循环。
- Suggested direction: 保留首阶段唯一项目，但建立真实的 registry-driven 选中和确认状态，不展示未来空选项。

### R-006: 指南对话框没有形成焦点边界

- Severity: Minor
- Requirement: `docs/engineering/FLY_SCENE_ARCHITECTURE.md` §7、§14。指南打开后焦点不得逃到背后画布或飞行控件，屏幕阅读器应获得符合当前阶段的操作名称。
- Evidence: 预飞时通过画布打开指南后，活动元素仍可回到 canvas。飞行中点击 help 后，初始焦点是 `Confirm and begin flight`，按一次 Tab 即进入指南背后的 `Hold main burner`。指南虽然标记 `aria-modal="true"`，但没有 focus trap、`inert` 或背景禁用；飞行中按钮名称仍为“开始飞行”，实际行为却是关闭指南并恢复。
- Location: `src/scenes/fly/flyScene.js:104-128`、`src/scenes/fly/flyScene.js:208-229`
- Impact: 键盘和屏幕阅读器用户可能离开模态指南，且飞行中收到错误的“开始飞行”动作语义；物理输入有 guard，因此未观察到直接飞行状态改变。
- Reproduction:
  1. 出发后点击无文字 help 控件。
  2. 确认焦点位于指南按钮。
  3. 按 Tab，观察焦点进入背景 burner 按钮。
- Expected: 焦点在指南内循环，背景内容不可聚焦；飞行中按钮语义为关闭/恢复指南。
- Actual: 焦点可以进入背景控件，且动作名称仍为 `Confirm and begin flight`。
- Acceptance criteria: 指南打开时 Tab/Shift+Tab 始终留在对话框；关闭后焦点恢复到开启控件；预飞和飞行中提供符合实际动作的名称。
