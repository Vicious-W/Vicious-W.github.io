## Executive summary

本轮目标（AUTO/MANUAL 双模式连续运行、单一控制权、原位人工接管、脉冲联锁、脉冲后传热、250 kW 平衡）在结构上已经达成，且实现方式符合规格的关键约束：`autoProgram.js` 确实只调用 `cmd.*` 而从不写入 `powerProxy`、棒位或温度（唯一写入是 `state.autoPhase`），AUTO 与 MANUAL 共用同一组指令、联锁与积分器；脉冲能量只经 `trans_eject_impulse` → 桥架/格栅刚体 → 接触点传给玻璃，没有直接改玻璃速度或扣耐久；`./scripts/run-validation.sh` 报告 PASS，本审查复跑 `npm test` 得到 100/100。

但有两处与已锁定规格不一致的行为缺陷，均为主要交互路径，且现有测试没有覆盖：

1. **R-001（Major）**：控制台上的 TRANS 提/插拨杆是死控件——在任何模式下都无法移动 TRANS 棒，与 `PROJECT_SPEC.md`「连续提插三根控制棒」冲突；

另有 3 项 Minor（切伦科夫可见阈值与资料基线不符、上述两条行为缺乏测试覆盖、WebGL 上下文丢失后无恢复路径）。由于存在 Major，结论为 `CHANGES_REQUIRED`。

## Major

### R-001: 控制台的 TRANS 提/插拨杆在任何模式下都无法移动 TRANS 棒（死控件）

- Severity: Major
- Requirement: `PROJECT_SPEC.md` §SOURCE 双模式连续运行：「`MANUAL` 允许用户通过无文字三维控制台启动、SCRAM、控制冷却泵、**连续提插三根控制棒**、切换运行/脉冲工况并触发满足联锁条件的脉冲」；同节「三维控制台……其形状、颜色和运动含义必须可辨认」；`docs/engineering/REACTOR_POOL_SYSTEM.md` RP-005「三套驱动拥有独立电机/气缸、连接件、棒位和限制状态」。
- Evidence: 代码路径唯一且确定：
  - `src/scenes/reactor/controlConsole.js:154-166` 对 `["SHIM","REG","TRANS"]` 三根棒都创建了 `hold` 热点 `TRANS_up` / `TRANS_dn`，按下调用 `commands.rodStart("TRANS", ±1)`；
  - `src/scenes/reactor/sessionController.js:206`：`if (name === "TRANS" && state.mode === "PULSE") return false;` —— PULSE 模式下指令直接被拒；
  - `src/scenes/reactor/sessionController.js:205`：`state.scrammed` 时被拒；
  - `src/scenes/reactor/sessionController.js:320-338`：OPERATE 模式下同一帧内先 `pos += vel*dt`（`ROD_DRIVE_RATE = 0.14`，第 74 行），随后 `else if (state.mode !== "PULSE") { r.TRANS.pos = Math.max(0, r.TRANS.pos - SCRAM_RATE * dt) }`（`SCRAM_RATE = 3.0`，第 75 行）。净变化为 `-2.86·dt`，被 `Math.max(0, …)` 钳在 0。
  - 因此三种模式（SHUTDOWN / OPERATE / PULSE）覆盖了全部可达状态，TRANS 棒位在人工控制下恒为 0。
  - `tests/run.mjs` 中没有任何一条断言驱动过 TRANS（全部 `rodStart` 调用只用 SHIM/REG，见 `tests/run.mjs:255,286,289,332`），所以 100/100 通过不构成反证。
- Location: `src/scenes/reactor/sessionController.js:204-214,320-338`；`src/scenes/reactor/controlConsole.js:154-166`
- Impact: 控制台上有两个可见、可点击、有独立配色（`COL.TRANS = 0xff8a3a`）的控件完全无响应。页面无任何文字，用户无法区分「这个控件被联锁禁止」和「这个控件坏了」；棒位小竖条与拨杆倾角也不会有任何反馈。更严重的是，`rodStart` 经 `manual()` 包装（`sessionController.js:310,479`），所以在 AUTO 运行期间按 TRANS 拨杆会触发 `claimManual()` 中止自动程序——用户付出了「失去自动运行」的代价却什么也没得到。
- Reproduction:
  1. 打开页面，点击控制台绿色 START 钮进入 MANUAL（`mode = OPERATE`，`scrammed = false`）；
  2. 按住橙色 TRANS 上拨杆（`__SOURCE_HOTSPOTS__()` 中 `name === "TRANS_up"`）持续数秒；
  3. 读取 `window.__SOURCE_STATE__.rod.TRANS.pos`；再切到 PULSE 模式重复一次。
- Expected: 与 SHIM/REG 一致，按住时 TRANS 棒位以驱动机构速率连续变化（或者：若「OPERATE 下 TRANS 必须保持在座」是有意的工程决定，则控制台不应提供该控件，或该控件必须以无文字方式明确显示为被联锁禁用）。
- Actual: 两种模式下 `rod.TRANS.pos` 始终为 `0.000000`；PULSE 模式下指令连 `true` 都不返回。
- Acceptance criteria: 在 `tests/run.mjs` 中新增断言：(a) 在允许 TRANS 人工定位的模式下，`rodStart("TRANS",+1)` 持续 3 s 后 `rod.TRANS.pos` 单调增长且增速 ≤ `ROD_DRIVE_RATE`，`rodStop("TRANS")` 后棒位保持不变；或 (b) 若确认 TRANS 不接受人工驱动，则控制台不再注册 `TRANS_up` / `TRANS_dn` 热点（`console3d.hotspots` 中不含该名称），或为其提供与脉冲钮同类的「联锁不满足即压暗」视觉状态，并在 `REACTOR_POOL_SYSTEM.md`/实现报告中登记该决定。两条路径都必须有对应测试。
- Suggested direction: 由实现者决定采用 (a) 还是 (b)；若采用 (a)，注意 `stepRods` 中「OPERATE 下 TRANS 回座」的强制项需要改成只在无人工驱动指令时生效。

### R-002: MANUAL 安全停堆后，任何控制台外交互都会静默重启完整 AUTO 程序

- Severity: Major
- Requirement: `docs/engineering/REACTOR_POOL_SYSTEM.md` §4.4：「MANUAL 重新启动完整 AUTO 前必须处于 SCRAM/安全停堆状态，**并通过控制台上的无文字 AUTO 控件明确触发**」；`PROJECT.md`：「从 MANUAL 重新进入完整 AUTO 只能在 SCRAM/安全停堆后由控制台上的无文字 AUTO 方钮触发」；`PROJECT_SPEC.md` 指明连续运行细节以 `REACTOR_POOL_SYSTEM.md` 为准。
- Evidence:
  - `src/scenes/reactor/physicalScene.js:318-321`：`interactOutsideConsole()` 无条件执行 `unlockAll(); session.requestAuto();`；
  - 该函数被绑定在全部控制台外交互上：左键点空处/拖玻璃（`physicalScene.js:630`）、右键/中键轨道相机（`:600`）、滚轮（`:702`）、`window` keydown（`:710`）；
  - `src/scenes/reactor/sessionController.js:278-291`：`requestAuto()` 的唯一门槛是 `isSafeShutdown()`，满足即改写 `controlOwner = "AUTO"` 并 `auto.reset()`（阶段回到 `INTERLOCKED_RESET`）；
  - 项目自带测试已经间接证明该状态可达：`tests/run.mjs:142-147` 在人工 SCRAM 后断言 `autoAvailable === true` 且 `requestAuto() === true`。缺的只是「触发者必须是 AUTO 方钮」这一约束。
- Location: `src/scenes/reactor/physicalScene.js:318-321,600,630,702,710`；`src/scenes/reactor/sessionController.js:278-291`
- Impact: 处于 MANUAL 的用户在完成一次人工 SCRAM 后，只要滚一下滚轮、按任意键、右键转一下相机或去拖一块玻璃，控制权就被交给 AUTO，自动程序从 `INTERLOCKED_RESET` 重新开跑（开泵、复位联锁、抽棒、直到再打一次历史脉冲）。用户既没有按 AUTO 方钮，也得不到「即将交出控制权」的提示；而这三类操作（转相机、缩放、拖玻璃）恰恰是本页面最常见的动作。同时这使规格要求的无文字 AUTO 方钮在该路径上形同虚设。
- Reproduction:
  1. 打开页面，点击控制台 START 钮进入 MANUAL；
  2. 按住 SHIM 上拨杆升到有功率，松开；
  3. 按红色 SCRAM 蘑菇钮，等待棒插到底、功率降到 `< 0.02`（此时 `__SOURCE_STATE__.autoAvailable === true`）；
  4. 不碰控制台，在画布空白处滚一下滚轮（或按任意键、右键拖动相机）；
  5. 读取 `__SOURCE_STATE__.controlOwner` 与 `autoPhase`。
- Expected: `controlOwner` 保持 `"MANUAL"`；只有点击控制台上的蓝色方形 AUTO 钮才会变成 `"AUTO"` 并把 `autoPhase` 复位为 `INTERLOCKED_RESET`。
- Actual: `controlOwner` 变为 `"AUTO"`，`autoPhase` 变为 `"INTERLOCKED_RESET"`，自动程序开始重放。
- Acceptance criteria: `interactOutsideConsole()` 只在 `controlOwner === "NONE"`（即真正的首次分流）时请求 AUTO；`controlOwner` 一旦为 `MANUAL`，控制台外交互只解锁/操作场景，不改变控制权。在 `tests/run.mjs` 增加断言：进入 MANUAL → SCRAM → 安全停堆后，模拟一次「控制台外交互」路径不改变 `controlOwner`，而显式调用 AUTO 控件对应的 `requestAuto()` 仍返回 `true` 并把 `autoPhase` 复位为 `INTERLOCKED_RESET`。
- Suggested direction: 首次分流与「重入 AUTO」是两件事，建议在场景层分开：`interactOutsideConsole()` 判断 `session.state.controlOwner === "NONE"` 才调用 `requestAuto()`，重入路径只保留控制台 AUTO 方钮（`controlConsole.js:196` 的 `commands.autoStart`）。

### R-003: 切伦科夫辉光在 250 W 代理就阶跃点亮，与「约 100 kW 后逐渐可见」的资料基线不符

- Severity: Minor
- Requirement: `docs/engineering/REACTOR_POOL_SYSTEM.md` §4.7：「切伦科夫在超过约 100 kW 的资料阈值后逐渐可见，**不瞬间开灯**」；按本项目标度 `powerProxy 1.0 = 250 kW`，100 kW 对应 `powerProxy ≈ 0.4`。
- Evidence: `src/scenes/reactor/waterSystem.js:227-229`：
  `const flash = min(1, powerProxy + pulsePowerProxy * 0.75)`；
  `glowMat.uniforms.uIntensity.value = flash > 0.001 ? 0.15 + flash * 1.4 : 0;`
  阈值 `0.001` = 250 W，比资料阈值低约 400 倍；且跨过阈值时强度从 `0` 阶跃到 `0.1514`（halo 同理，`0 → 0.0801`），正是「瞬间开灯」。
- Location: `src/scenes/reactor/waterSystem.js:227-229`
- Impact: AUTO 的 `LOW_POWER_APPROACH`/脉冲前低功率阶段（`powerProxy` 在 `1e-5…4e-4` 量级）虽仍在阈值下，但一旦进入 `STEADY_POWER_ASCENT` 早期（远低于 100 kW）池内就出现明显蓝光，削弱了「低功率临界 → 升功率 → 全功率」这条可观察因果链的分辨力，并与工程基线对不上。不影响主要流程可用性。
- Reproduction:
  1. 打开页面，控制台外点击进入 AUTO；
  2. 用 `__SOURCE_ADVANCE__()` 推进到 `STEADY_POWER_ASCENT` 早期，读取 `__SOURCE_STATE__.powerProxy`；
  3. 观察池内切伦科夫辉光已明显可见（`powerProxy` 仅几个百分之一，即几 kW 代理）。
- Expected: 辉光强度在 `powerProxy ≈ 0.4` 附近开始从 0 连续增长（例如用 `smoothstep(0.3, 0.6, powerProxy)` 一类的软阈值），脉冲通道另行处理。
- Actual: `powerProxy > 0.001`（250 W）即以 0.15 的固定基值阶跃点亮。
- Acceptance criteria: 稳态通道在 `powerProxy < 0.3` 时 `uIntensity === 0`，在 `0.3 → 0.6` 区间连续单调增长且无阶跃（可用取样比较相邻功率点的强度差）；脉冲通道的强闪保持不变，`prefers-reduced-motion` 下的压制系数不变。
