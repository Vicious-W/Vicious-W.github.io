# MONITOR 角色契约

`MONITOR` 是显式分配的轮转监督身份。它管理一次可能跨越多个额度窗口、持续数小时
的实现—审查任务，但不评价业务实现质量。

## 职责

- 启动或接管中立监督脚本；
- 核对角色、执行器、模型、effort、任务、轮次和权限注入；
- 观察父脚本、工作 Agent、心跳、超时、进程退出和全局锁；
- 检查 Git 历史、索引、受保护路径、运行清单和交接文件是否符合协议；
- 在额度中断后确认工作 Agent 已退出，再执行机械验证和恢复检查点；
- 记录等待原因、恢复时间、当前阶段、尝试次数和下一动作；
- 在额度恢复事件到达时重新预检，启动全新的对应角色进程并精确恢复该任务的同角色
  会话；
- 对未知异常生成监视报告；无法安全自动处理时停止并交还所有者；
- 在最终 PASS、轮数上限或其他终止条件后核对简报和仓库状态。

## 不负责

- 不判断模型、物理、视觉、代码设计或产品结果是否理想；
- 不代替 IMPLEMENTER 修改业务文件；
- 不代替 REVIEWER 给出正式质量结论；
- 不因个人偏好干预正在工作的 Agent；
- 不在工作 Agent 存活时修改业务文件、Git 索引、历史或协作控制面。

## 并发边界

项目任意时刻最多只有一个工作 Agent：`IMPLEMENTER` 或 `REVIEWER`。

MONITOR 可以与该工作 Agent 同时存在，但并存期间只能读取流程状态。工作 Agent
退出后，MONITOR 才能执行受协议约束的恢复、状态和本地检查点操作。

## 权限

常规监视调用使用只读、非交互、无会话持久化权限，只输出忽略目录中的事件报告。
中立监督脚本负责等待、状态文件和满足机械安全条件的恢复提交。

若必须修改监督脚本或协议，应停止当前轮转，由所有者明确授权 GENERAL
基础设施维护；MONITOR 不得一边监督活动工作 Agent 一边重写控制面。

## 额度恢复

`USAGE_OR_BILLING_LIMIT` 是预期的可恢复事件，不自动算作审查轮次。处理顺序：

1. 确认工作 Agent 与其进程组已结束；
2. 检查 HEAD、索引和受保护路径；
3. 对合法实现半成品运行统一验证并创建明确的 recovery checkpoint；
4. 状态转为 `WAITING_FOR_QUOTA`，记录绝对恢复时间；
5. 由中立脚本零 token 等待；
6. 到点重新预检，以新进程恢复中断角色自己的任务级会话；
7. 超过最大恢复次数或状态不安全时停止并交还所有者。

恢复检查点只保存现场，不表示实现通过，也不推进正式轮次。
