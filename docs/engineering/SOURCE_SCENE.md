# SOURCE 场景工程设计基线

DESIGN_STATUS: ACTIVE

本文件定义当前唯一场景《SOURCE》的空间关系、连续运行、跨系统物理耦合、
重置规则和验收条件。完整反应堆池系统见 `REACTOR_POOL_SYSTEM.md`，堆芯内部结构
见 `REACTOR_MODEL.md`；实验室、地下设备、自由相机、水体光学、辉光粒子、玻璃
建筑和双控制台见 `SOURCE_LAB_OPTICS.md`。

## 1. 场景定义

- 场景正式名称：`SOURCE`；
- 当前网站只包含这个场景；
- 未来可以增加其他场景，但不属于当前任务；
- 页面保持全屏、无可见文字、以蓝色为核心颜色；
- 场景主要对象分为两个大部分：完整 Pavia TRIGA Mark II 反应堆池系统，以及位于
  其上部安全格栅的实心玻璃方块；
- 反应堆池系统内部包含反应堆、水箱、生物屏蔽、轻水、上部桥架/格栅、控制机构、
  实验设施、仪器、电缆/气路和冷却设备；
- 主要物体、运动、损伤、声音和系统响应必须来自三维几何与可解释的物理状态。

不使用照片、背景图、预渲染画面或整面 shader 代替任一主要系统。shader 只能表达
真实几何上的玻璃、水体、照明、折射、反射和切伦科夫光学。

## 2. 空间拓扑

从下到上：

```text
实心玻璃方块
    ↕ 接触、摩擦、冲量、损伤
放下并锁定的上部安全格栅/透明下衬
    ↕ 桥架有限刚度、阻尼和机构载荷
轻水体积与水面
    ↕ 流体、光学、局部棒运动和脉冲后热传递
Pavia TRIGA Mark II 堆芯、池底与冷却/实验结构
```

必须满足：

- 反应堆固定在池体下部并浸没于轻水；
- 轻水是具有边界、深度和表面的独立体积；
- 上部桥架和安全格栅是反应堆池系统的真实类型工程结构，不是为玻璃临时添加的
  隐形地板；
- 玻璃初始位置位于放下并锁定的实体格栅上，不接触水面；
- 反应堆池、轻水、格栅和玻璃共享同一世界坐标、场景时钟和物理事件；
- 从视差、遮挡、折射、碰撞、管线连接或状态传播能够确认各系统的空间关系。

## 3. 会话与重置

每次打开页面或刷新页面都创建一个新的 SOURCE 会话。初始化必须是确定性的：

1. 销毁上一会话的计时器、音频 voice、约束、刚体和碎片；
2. 反应堆回到停堆/预启动状态，控制棒、功率、温度和流量代理归零或进入明确初值；
3. 轻水回到静水平衡状态，清除旧波动、速度场和外部冲量；
4. 上部格栅回到放下并锁定状态，桥架弹性位移和振动归零；
5. 删除全部玻璃碎片、裂纹和累计损伤；
6. 按固定初始布局在格栅上重建每块玻璃，耐久恢复为 `1.0`；
7. 重置场景时钟、AUTO 调度器和 MANUAL 命令状态，等待第一次有效用户交互；
8. 不从 `localStorage`、IndexedDB 或服务端恢复上次损伤和位置。

同一页面会话内的玻璃位置和耐久必须持续存在，除非页面刷新或显式建立新的 SOURCE
会话。窗口 resize、设备旋转、标签页隐藏或 WebGL 上下文恢复不得被当成新会话。

## 4. 反应堆池资料与运行边界

反应堆池的结构、部件、环境设备、线缆/管路、连续运行、历史脉冲、冷却回路和
格栅载荷路径统一以 `REACTOR_POOL_SYSTEM.md` 为工程基线。

SOURCE 不再把“启动效果”和“运行效果”当成两个单独设计的表演。AUTO 与 MANUAL
共享同一个反应堆、轻水、结构和玻璃状态；AUTO 是对真实控制命令的调度，不是第二
套动画。控制权切换后，棒位、功率、燃料温度、轻水、冷却设备、结构振动、声音和
玻璃状态都继承切换前的物理结果。

### 4.1 声音来源

可信的声音来源：

- 控制棒电机、齿条、联轴器和位置机构；
- 电磁铁吸合或释放；
- 历史脉冲工况中的气动瞬发机构；
- 通风、二次冷却和其他已建模辅助设备；
- 水流、表面波、物体入水和池体结构响应；
- 玻璃碰撞、滑动、滚动、开裂和破碎。

不把“核反应”直接合成为持续的科幻低频嗡鸣。任何持续声音都必须指向一个可见或
已建模的机械、流体或电气音源。

## 5. SOURCE 双模式连续运行

第一次有效指针、触控或键盘交互同时解锁音频并释放场景时钟。在此之前，反应堆池、
轻水、格栅和玻璃保持可见的联锁复位状态，不开始视觉运行，也不漏掉声音。

- 控制台热点以外的首次交互选择 AUTO；
- 控制台热点上的首次交互选择 MANUAL，并执行该控件指令；
- AUTO 运行中使用控制台会原位人工接管；
- MANUAL 返回完整 AUTO 前必须先进入 SCRAM/安全停堆状态；
- 控制台提供无文字 AUTO 控件与当前控制权状态反馈；
- AUTO 和 MANUAL 共用同一个 session controller、命令 API、联锁和物理积分器。

AUTO 可以使用以下可测试阶段：

```text
INTERLOCKED_RESET
  → AUXILIARIES_READY
  → LOW_POWER_APPROACH
  → PULSE_ARMED
  → PULSE
  → POST_PULSE_HEAT_TRANSFER
  → STEADY_POWER_ASCENT
  → FULL_POWER_EQUILIBRIUM
```

这些名称只用于观测和测试，不代表八段互不相干的动画。每个阶段都要有：

- 进入条件；
- 明确持续时间或物理终止条件；
- 允许运动的部件；
- 对功率、温度、轻水和音频的影响；
- 降低动态效果时的替代状态；
- 可由测试读取的状态值。

Chrome 等浏览器通常要求 Web Audio 在首次用户手势后 `resume()`，页面不能保证
首次访问时自动播放声音。

来源：
[Chromium Autoplay Policy](https://www.chromium.org/audio-video/autoplay/)

不得通过要求用户修改浏览器策略、静音绕过或隐藏媒体元素规避权限。具体连续运行、
棒位、脉冲、传热和最终功率平衡见 `REACTOR_POOL_SYSTEM.md` 第 4 节。

## 6. 轻水物理系统

轻水至少由三个互相一致的层次组成。

### 6.1 几何与体积

- 独立水体边界；
- 明确水面高度、池壁和池底；
- 堆芯和池内结构真实浸没；
- 水体不能只是一张透明平面；
- 水体对象可以独立显示、隐藏和调试。

### 6.2 动力学

实时模型至少表达：

- 静水状态与重力方向；
- 水面传播、反射、阻尼和边界条件；
- 反应堆机械/脉冲事件产生的局部冲量；
- 玻璃或碎片入水产生的位移、波和阻力；
- 浸没物体的浮力、阻力和角阻尼；
- 能量输入停止后波动衰减，不存在永久装饰波。

可采用适合浏览器实时运行的二维高度场或浅水近似表达水面；如果物体进入水体，
刚体仍由三维物理世界计算，水面求解器与刚体通过冲量和排水量耦合。近似必须写入
实现报告。

### 6.3 光学

- 折射、反射和菲涅尔随视角变化；
- 深度吸收和水下散射随光程变化；
- 池壁、堆芯和玻璃通过同一水体产生一致光学关系；
- 切伦科夫光位于水体内部；
- 光学 shader 不得生成虚假的池体、堆芯或玻璃几何。

### 6.4 声音

- 波、入水、撞击和持续流动分别使用不同物理数据；
- 强度由冲量、速度、排水量或流速代理驱动；
- 无事件时不得循环播放“水声”；
- 音量、并发和峰值受全局限制。

## 7. 玻璃物理与耐久

### 7.1 基础刚体

每块玻璃保留独立：

- 三维几何和材质；
- 质量、质心和惯性；
- 位置、旋转、线速度和角速度；
- 碰撞形状、摩擦、恢复系数和阻尼；
- 耐久、损伤阶段和裂纹/碎片状态。

### 7.2 损伤输入

损伤只能来自可检查的接触数据：

- 接触法向相对速度；
- 法向冲量；
- 有效碰撞质量；
- 撞击点与质心的距离；
- 角速度和局部受力；
- 碰撞对象的材料类别；
- 已有裂纹造成的强度降低。

最低冲击能量代理：

```text
impactEnergy = 0.5 × effectiveMass × normalRelativeSpeed²
```

该代理用于稳定地映射网页物理事件，不声称能预测真实玻璃断裂力学。阈值必须通过
统一尺度和重复测试校准，不能按随机数决定损伤。

### 7.3 损伤阶段

```text
INTACT
  → MICRO_DAMAGED
  → CRACKED
  → FRACTURED
```

- 低于弹性阈值：不损伤；
- 中等冲击：累计不可见或轻微损伤，降低后续阈值；
- 较强冲击：从接触点产生可见裂纹，刚度/声音发生变化；
- 超过破碎阈值：原刚体停止作为完整方块存在，生成独立碎片；
- 同一会话内损伤不可自行恢复；
- 刷新或新会话时全部恢复为 `INTACT`、耐久 `1.0`。

### 7.4 裂纹与破碎几何

- 裂纹纹理或 shader 只能表达表面细节；
- 真正破碎时主要碎片必须拥有独立三维几何和刚体；
- 碎片的初速度和角速度来自破碎前动量及接触冲量；
- 碎片可以继续碰撞、入水和发声；
- 性能上可以限制碎片数量，但不能用一张破碎图片替代所有碎片；
- 任何碎片合并、休眠或回收策略都不能导致正在观察的碎片突然消失。

### 7.5 玻璃声音

至少区分：

- 完整玻璃的碰撞；
- 已开裂玻璃的碰撞；
- 裂纹扩展；
- 破碎瞬态；
- 碎片二次碰撞；
- 滑动和滚动。

声音由同一碰撞/损伤事件生成，不允许视觉破碎与音频使用互不相关的计时器。

## 8. 跨系统耦合

SOURCE 的事件链至少包括：

```text
页面会话开始
  → 反应堆池与玻璃统一复位并等待交互
  → 第一次交互解锁音频和连续运行
  → 辅助设备/联锁/控制棒/功率/温度/流量连续变化
  → 历史脉冲的气动机构、切伦科夫和燃料温度响应
  → 机构反力经桥架/格栅传给玻璃，水下棒运动局部扰动轻水
  → 脉冲后燃料热量进入轻水、自然循环和三回路
  → 玻璃接触产生运动、损伤和声音，掉入水中的碎片再与轻水耦合
  → 系统在阻尼、换热和控制作用下进入全功率平衡
```

不允许：

- 反应堆设备、轻水、格栅和玻璃各自使用不相关的循环时间；
- 用屏幕抖动冒充水体或结构振动；
- 在 `PULSE` 时直接给玻璃随机速度或直接扣耐久；
- 只改变颜色而不改变对应物理状态；
- 玻璃破碎但原碰撞体仍作为完整方块参与物理；
- 刷新后保留上一会话的碎片或损伤。

## 9. 时间步、确定性与性能

- 刚体、水面和连续运行控制器使用明确的固定或半固定时间步；
- 毫秒脉冲使用独立高频/解析代理，不依赖渲染帧率捕捉峰值；
- 渲染帧率变化不能显著改变运行顺序、损伤结果和波速；
- 页面不可见时暂停或降频，恢复时不得一次补算巨量时间；
- 初始布局和联锁复位状态使用固定种子或固定数据；
- GPU/CPU 预算不足时先降低不可见细节、求解分辨率和休眠对象成本；
- 不得通过取消主要部件独立性、取消水物理或取消碎片刚体来伪造性能达标；
- `prefers-reduced-motion: reduce` 下禁止强闪、屏幕震动和大幅水面运动，直接进入
  安全静态或低动态状态，同时保留结构可检查性。

## 10. 验收

### 10.1 会话

- 打开和刷新都从同一规范初始状态开始；
- 第一次交互前保持联锁复位，第一次交互只启动一次完整运行程序；
- 玻璃位置、耐久、裂纹和碎片正确复位；
- resize 和标签页切换不触发错误复位；
- 连续运行阶段和主要物理状态可由测试读取。

### 10.2 连续运行与反应堆池

- 生物屏蔽、水箱、桥架、格栅、驱动、仪器、实验设施和冷却回路形成完整系统；
- 辅助设备、低功率临界、历史脉冲、脉冲后传热和 250 kW 平衡保持事实顺序；
- 脉冲是毫秒事件，不表现为核爆或数秒高功率；
- 结构振动、轻水响应、玻璃运动和声音来自各自真实载荷路径；
- 最终平衡继承此前棒位、温度、流量、水体和玻璃状态，不是另起装饰循环。

### 10.3 轻水

- 是独立三维体积与水面系统；
- 波动由水下棒运动、反应堆设备、入水碎片或边界事件触发并衰减；
- 脉冲后的燃料传热、自然循环和三回路响应使用正确时间尺度；
- 光学、动力学和声音使用一致状态；
- 不加载水面背景图或预渲染水体。

### 10.4 玻璃

- 耐久随可复现的碰撞能量变化；
- 实心玻璃由实体格栅支承，不漂浮在轻水上；
- 脉冲只通过桥架/格栅载荷路径影响玻璃，不直接修改刚体速度或耐久；
- 低能接触不持续扣除耐久；
- 裂纹从接触事件产生；
- 破碎后主要碎片具有独立几何、刚体、声音和水体交互；
- 刷新后完整恢复。

### 10.5 浏览器

- 使用 Playwright MCP 检查 `390 × 844`、`768 × 1024`、`1440 × 900`；
- 验证首次交互、连续运行、脉冲、脉冲后水体/玻璃响应、最终平衡、玻璃损伤、
  破碎、刷新复位和音频解锁；
- console 没有影响运行的错误；
- 记录各视口的性能和未验证声音听感。

## 11. 已锁定决定

### S-001：连续运行包含一次历史脉冲

第一次交互后执行 `REACTOR_POOL_SYSTEM.md` 定义的连续运行程序。程序从联锁复位和
低功率临界条件出发，包含一次有 Pavia 历史资料支持的脉冲，然后经过脉冲后传热、
稳态功率提升和全功率平衡。脉冲不能混入正常抽棒过程，也不能表现为爆炸。

### S-002：第一次交互启动全部运行

页面加载或刷新后保持可见的联锁复位状态。第一次指针、触控或键盘交互同时解锁
Web Audio、释放场景时钟并开始完整连续运行，不补播此前事件，也不让视觉提前运行。

### S-003：实心玻璃由真实类型格栅支承

玻璃位于放下并锁定的上部铝制安全格栅和透明实体下衬上。格栅由真实类型 TRIGA
桥架支承并与反应堆池结构相连，既是可见模型也是物理碰撞体。玻璃不是现实反应堆
部件；它是 SOURCE 放置在真实工程支承结构上的交互对象。

### S-004：完整实验室和地下设备层

SOURCE 建立可自由观察的反应堆大厅与地下设备层。地面和地下设备按真实功能拓扑
连接；没有公开 Pavia 竣工图的具体位置必须标记为代理布局，不伪造精确设施事实。

### S-005：自由观察相机

相机允许轨道观察、平移、连续缩放和自由飞行，可以进入水下、堆芯附近、地板以下
和地下设备层。观察相机不参与刚体碰撞，不改变会话、控制权或设备物理状态。

### S-006：清澈轻水和局部切伦科夫

轻水必须让堆芯可见。切伦科夫位于堆芯附近水体并由功率状态驱动，使用体积光与
粒子视觉代理增强空间感；粒子不是可碰撞物质，也不把整池水染成常亮蓝色。

### S-007：两类建筑玻璃

墙壁和天花板由固定、不可抓取的玻璃砖构成；地板玻璃砖是由透明结构层承托的动态
刚体，可移动、损伤、破碎并在刷新时复位。透明结构层不替代池口真实安全格栅。

### S-008：抓取期间的受控朝向

抓取动态玻璃时，鼠标只控制水平位置，`W/S` 控制上下，`A/D` 只绕世界竖直轴偏航。
抓取清除随机角速度并锁定俯仰/翻滚；释放不注入随机旋转，之后真实碰撞可以旋转。

### S-009：MANUAL 与 AUTO 使用独立实体面板

保留现有 MANUAL 控制台，并在旁边新增 AUTO 控制台。两者拥有独立三维几何和反馈，
但共享唯一 session controller、命令、联锁和反应堆状态，不能同时驱动设备。
