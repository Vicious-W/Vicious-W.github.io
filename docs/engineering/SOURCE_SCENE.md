# SOURCE 场景工程设计基线

DESIGN_STATUS: NEEDS_OWNER_DECISION

本文件定义当前唯一场景《SOURCE》的空间关系、会话生命周期、跨系统物理耦合、
重置规则和验收条件。反应堆内部结构的详细基线见 `REACTOR_MODEL.md`。

## 1. 场景定义

- 场景正式名称：`SOURCE`；
- 当前网站只包含这个场景；
- 未来可以增加其他场景，但不属于当前任务；
- 页面保持全屏、无可见文字、以蓝色为核心颜色；
- 场景主要系统只有三个：Pavia TRIGA Mark II、轻水、玻璃方块；
- 主要物体、运动、损伤、声音和系统响应必须来自三维几何与可解释的物理状态。

不使用照片、背景图、预渲染画面或整面 shader 代替任一主要系统。shader 只能表达
真实几何上的玻璃、水体、照明、折射、反射和切伦科夫光学。

## 2. 空间拓扑

从下到上：

```text
玻璃方块层
    ↕ 接触、支承、浮力或入水关系（S-003 待决定）
轻水体积与水面
    ↕ 流体、光学、压力/振动和热状态
Pavia TRIGA Mark II 堆芯与池底结构
```

必须满足：

- 反应堆固定在池体下部并浸没于轻水；
- 轻水是具有边界、深度和表面的独立体积；
- 玻璃初始位置位于轻水顶部区域；
- 三层共享同一世界坐标和时间线，不能分别播放互不相关的动画；
- 从视差、遮挡、折射、碰撞或状态传播能够确认三者的空间关系。

## 3. 会话与重置

每次打开页面或刷新页面都创建一个新的 SOURCE 会话。初始化必须是确定性的：

1. 销毁上一会话的计时器、音频 voice、约束、刚体和碎片；
2. 反应堆回到停堆/预启动状态，控制棒、功率、温度和流量代理归零或进入明确初值；
3. 轻水回到静水平衡状态，清除旧波动、速度场和外部冲量；
4. 删除全部玻璃碎片、裂纹和累计损伤；
5. 按固定初始布局重建每块玻璃，耐久恢复为 `1.0`；
6. 重置场景时钟和启动状态机；
7. 不从 `localStorage`、IndexedDB 或服务端恢复上次损伤和位置。

同一页面会话内的玻璃位置和耐久必须持续存在，除非页面刷新或显式建立新的 SOURCE
会话。窗口 resize、设备旋转、标签页隐藏或 WebGL 上下文恢复不得被当成新会话。

## 4. 真实运行资料边界

### 4.1 常规 TRIGA 启动

IAEA 的 TRIGA Mark II 启动示范把启动分为：

- 启动检查与预启动诊断；
- SCRAM 和保护回路检查；
- 控制棒分步抽出；
- 观察反应堆周期并控制功率上升；
- 在目标功率稳定；
- 持续监测燃料温度、水温、辐射和功率。

来源：
[IAEA Reactor Startup Demonstration](https://nucleus.iaea.org/sites/connect/RRIHpublic/CompendiumDB/Shared%20Documents/Morocco/Protocols%20in%20PDF/Morocco_7%20Reactor%20Startup%20Demonstration.pdf)

Pavia 资料进一步确认：

- SHIM 和 REG 棒以固定低速抽出，避免突然加入正反应性；
- TRANS、SHIM、REG 三根棒承担不同功能；
- Ra–Be 中子源用于让启动阶段的中子通量可检测；
- Pavia 稳态额定功率为 250 kW；
- Pavia 的切伦科夫光在临界功率超过约 100 kW 时明显可见。

来源：

- [IAEA / Pavia Control Rod Calibration](https://nucleus.iaea.org/sites/connect/RRIHpublic/CompendiumDB/Shared%20Documents/Italy/Protocols%20in%20PDF/1_Control_rod_calibration_in_a_TRIGA_reactor.pdf)
- [University of Pavia LENA — The Reactor](https://lena.unipv.it/en/the-reactor/)

因此，正常启动应表现为有顺序的检查、机构动作、功率爬升和稳定，不应凭空出现
瞬时强闪光、猛烈机械冲击或大幅水面振动。

### 4.2 Pavia 历史脉冲运行

Pavia TRIGA Mark II 历史上具备脉冲运行能力，曾以约 250 MW 峰值运行几十毫秒，
并在 1980 年代中期以前完成数百次脉冲。脉冲与正常启动是不同工况。

如果 SOURCE 需要瞬间强烈切伦科夫闪光、气动机构声和明显的水体/结构响应，应把它
建模为独立的 `PULSE` 事件，不能称为正常启动本身。

### 4.3 声音来源

可信的声音来源：

- 控制棒电机、齿条、联轴器和位置机构；
- 电磁铁吸合或释放；
- 历史脉冲工况中的气动瞬发机构；
- 通风、二次冷却和其他已建模辅助设备；
- 水流、表面波、物体入水和池体结构响应；
- 玻璃碰撞、滑动、滚动、开裂和破碎。

不把“核反应”直接合成为持续的科幻低频嗡鸣。任何持续声音都必须指向一个可见或
已建模的机械、流体或电气音源。

## 5. SOURCE 生命周期

状态机必须是唯一时间源：

```text
RESET
  → ACTIVATION
  → PRESTART
  → ROD_WITHDRAWAL
  → POWER_ASCENT
  → STABILIZATION
  → STEADY
```

如果所有者选择历史脉冲展示，则增加：

```text
STABILIZATION
  → PULSE_ARMED
  → PULSE
  → TRANSIENT_DECAY
  → STEADY
```

任何状态转换都要有：

- 进入条件；
- 明确持续时间或物理终止条件；
- 允许运动的部件；
- 对功率、温度、轻水和音频的影响；
- 降低动态效果时的替代状态；
- 可由测试读取的状态值。

### 5.1 RESET

- 建立规范初始位置；
- 玻璃耐久为 `1.0`；
- 轻水平静；
- 反应堆处于停堆或 SCRAM 后的安全棒位；
- 不产生声音和持续外力。

### 5.2 ACTIVATION

用于处理浏览器音频权限。Chrome 等浏览器通常要求 Web Audio 在首次用户手势后
`resume()`，页面不能保证首次访问时自动播放声音。

来源：
[Chromium Autoplay Policy](https://www.chromium.org/audio-video/autoplay/)

具体激活方式见 S-002。不得通过要求用户修改浏览器策略、静音绕过或隐藏媒体元素
规避权限。

### 5.3 PRESTART

网页可以压缩真实检查所需时间，但必须保持因果顺序：

- 轻水和必要辅助系统状态确认；
- 仪器和保护状态建立；
- 控制棒驱动、磁耦合和 SCRAM 机构检查；
- 中子源/启动通量代理建立；
- 检查完成后才允许抽棒。

检查不是文字 UI；通过仪器对象、机构动作、灯光状态或声音在三维场景内表达。

### 5.4 ROD_WITHDRAWAL

- SHIM、REG、TRANS 拥有独立状态；
- 按 Pavia 功能与位置建模；
- 正常启动使用受控、有限速度的棒位改变；
- 不能让全部控制棒以相同正弦函数同步运动；
- 棒位变化驱动反应性代理，不直接手工设置辉光强度。

### 5.5 POWER_ASCENT

最低因果链：

```text
rodPosition[]
  → reactivityProxy
  → powerProxy
  → fuelTemperatureProxy
  → negativeTemperatureFeedback
  → waterTemperature/flowProxy
  → Cherenkov 与仪器响应
```

允许使用定性代理，不允许显示未经核工程验证的真实功率、安全裕量或温度数值。

### 5.6 STABILIZATION 与 STEADY

- 控制棒从功率提升转为稳定调节；
- 功率、燃料温度、水温和自然循环趋于稳定，不是完全静止；
- 切伦科夫辉光随功率状态稳定，只保留有物理来源的小幅波动；
- 轻水的启动扰动逐渐耗散；
- 玻璃继续由刚体、耐久和水体/支承关系控制；
- 所有持续音频由稳态机械或流体状态驱动。

## 6. 轻水物理系统

轻水至少由三个互相一致的层次组成。

### 6.1 几何与体积

- 独立水体边界；
- 明确水面高度、池壁和池底；
- 堆芯和池内结构真实浸没；
- 水体不能只是一张透明平面；
- 水体对象可以独立显示、隐藏和调试。

### 6.2 动力学

实时模型至少表达：

- 静水状态与重力方向；
- 水面传播、反射、阻尼和边界条件；
- 反应堆机械/脉冲事件产生的局部冲量；
- 玻璃或碎片入水产生的位移、波和阻力；
- 浸没物体的浮力、阻力和角阻尼；
- 能量输入停止后波动衰减，不存在永久装饰波。

可采用适合浏览器实时运行的二维高度场或浅水近似表达水面；如果物体进入水体，
刚体仍由三维物理世界计算，水面求解器与刚体通过冲量和排水量耦合。近似必须写入
实现报告。

### 6.3 光学

- 折射、反射和菲涅尔随视角变化；
- 深度吸收和水下散射随光程变化；
- 池壁、堆芯和玻璃通过同一水体产生一致光学关系；
- 切伦科夫光位于水体内部；
- 光学 shader 不得生成虚假的池体、堆芯或玻璃几何。

### 6.4 声音

- 波、入水、撞击和持续流动分别使用不同物理数据；
- 强度由冲量、速度、排水量或流速代理驱动；
- 无事件时不得循环播放“水声”；
- 音量、并发和峰值受全局限制。

## 7. 玻璃物理与耐久

### 7.1 基础刚体

每块玻璃保留独立：

- 三维几何和材质；
- 质量、质心和惯性；
- 位置、旋转、线速度和角速度；
- 碰撞形状、摩擦、恢复系数和阻尼；
- 耐久、损伤阶段和裂纹/碎片状态。

### 7.2 损伤输入

损伤只能来自可检查的接触数据：

- 接触法向相对速度；
- 法向冲量；
- 有效碰撞质量；
- 撞击点与质心的距离；
- 角速度和局部受力；
- 碰撞对象的材料类别；
- 已有裂纹造成的强度降低。

最低冲击能量代理：

```text
impactEnergy = 0.5 × effectiveMass × normalRelativeSpeed²
```

该代理用于稳定地映射网页物理事件，不声称能预测真实玻璃断裂力学。阈值必须通过
统一尺度和重复测试校准，不能按随机数决定损伤。

### 7.3 损伤阶段

```text
INTACT
  → MICRO_DAMAGED
  → CRACKED
  → FRACTURED
```

- 低于弹性阈值：不损伤；
- 中等冲击：累计不可见或轻微损伤，降低后续阈值；
- 较强冲击：从接触点产生可见裂纹，刚度/声音发生变化；
- 超过破碎阈值：原刚体停止作为完整方块存在，生成独立碎片；
- 同一会话内损伤不可自行恢复；
- 刷新或新会话时全部恢复为 `INTACT`、耐久 `1.0`。

### 7.4 裂纹与破碎几何

- 裂纹纹理或 shader 只能表达表面细节；
- 真正破碎时主要碎片必须拥有独立三维几何和刚体；
- 碎片的初速度和角速度来自破碎前动量及接触冲量；
- 碎片可以继续碰撞、入水和发声；
- 性能上可以限制碎片数量，但不能用一张破碎图片替代所有碎片；
- 任何碎片合并、休眠或回收策略都不能导致正在观察的碎片突然消失。

### 7.5 玻璃声音

至少区分：

- 完整玻璃的碰撞；
- 已开裂玻璃的碰撞；
- 裂纹扩展；
- 破碎瞬态；
- 碎片二次碰撞；
- 滑动和滚动。

声音由同一碰撞/损伤事件生成，不允许视觉破碎与音频使用互不相关的计时器。

## 8. 跨系统耦合

SOURCE 的事件链至少包括：

```text
页面会话开始
  → 三系统复位
  → 反应堆启动状态机
  → 棒位/功率/温度/流量状态变化
  → 切伦科夫、轻水和真实音源响应
  → 轻水将冲量/浮力/阻力传给玻璃或碎片
  → 玻璃运动产生碰撞、损伤、波和声音
  → 能量耗散后进入稳态
```

不允许：

- 反应堆、水和玻璃各自使用不相关的循环时间；
- 用屏幕抖动冒充水体或结构振动；
- 只改变颜色而不改变对应物理状态；
- 玻璃破碎但原碰撞体仍作为完整方块参与物理；
- 刷新后保留上一会话的碎片或损伤。

## 9. 时间步、确定性与性能

- 刚体、水面和状态机使用明确的固定或半固定时间步；
- 渲染帧率变化不能显著改变启动顺序、损伤结果和波速；
- 页面不可见时暂停或降频，恢复时不得一次补算巨量时间；
- 初始布局和启动状态使用固定种子或固定数据；
- GPU/CPU 预算不足时先降低不可见细节、求解分辨率和休眠对象成本；
- 不得通过取消主要部件独立性、取消水物理或取消碎片刚体来伪造性能达标；
- `prefers-reduced-motion: reduce` 下禁止强闪、屏幕震动和大幅水面运动，直接进入
  安全静态或低动态状态，同时保留结构可检查性。

## 10. 验收

### 10.1 会话

- 打开和刷新都从同一规范初始状态开始；
- 玻璃位置、耐久、裂纹和碎片正确复位；
- resize 和标签页切换不触发错误复位；
- 场景生命周期可由测试读取。

### 10.2 启动与稳态

- 启动阶段具有明确状态顺序和因果关系；
- 正常启动不包含无依据的脉冲现象；
- 若启用脉冲，它作为独立状态并使用 Pavia 历史资料；
- 稳态不是与系统状态无关的装饰循环；
- 反应堆、水和玻璃响应共享同一事件链。

### 10.3 轻水

- 是独立三维体积与水面系统；
- 波动由反应堆、玻璃或边界事件触发并衰减；
- 光学、动力学和声音使用一致状态；
- 不加载水面背景图或预渲染水体。

### 10.4 玻璃

- 耐久随可复现的碰撞能量变化；
- 低能接触不持续扣除耐久；
- 裂纹从接触事件产生；
- 破碎后主要碎片具有独立几何、刚体、声音和水体交互；
- 刷新后完整恢复。

### 10.5 浏览器

- 使用 Playwright MCP 检查 `390 × 844`、`768 × 1024`、`1440 × 900`；
- 验证初始状态、启动状态转换、稳态、玻璃损伤、破碎、刷新复位和音频解锁；
- console 没有影响运行的错误；
- 记录各视口的性能和未验证声音听感。

## 11. 所有者决定

### S-001：正常启动与历史脉冲

选择一项：

1. 只模拟正常启动：预检、抽棒、功率爬升、切伦科夫逐渐增强、稳定运行；
2. 正常启动后自动执行一次历史脉冲：增加瞬时强光、气动机构声和有界的水体/结构
   响应，然后衰减进入稳态。

不得把第 2 项的脉冲直接命名为普通启动。

### S-002：首次声音与启动触发

选择一项：

1. 页面立即开始视觉启动；首次用户手势只解锁当时及之后的声音，之前声音不补播；
2. 页面加载后保持复位状态，首次指针/触控/键盘手势同时解锁声音并启动完整时间线。

第 2 项能保证音画同步，但启动发生在首次交互而不是 HTML 完成加载的瞬间。

### S-003：玻璃为什么位于水面顶部

实心玻璃密度高于水，不能无支承漂浮。选择一项：

1. 实心玻璃放在水面上方的真实支承格架或平台上；
2. 使用密封空心玻璃块，以平均密度和浮力保持在水面；
3. 实心玻璃从水面上方开始，但允许落入轻水并下沉。

选定前不得用隐形平面托住玻璃，也不得把实心玻璃写成自然漂浮。
